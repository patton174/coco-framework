# Coco Framework 文档前端视觉重构设计

## 1. 目标

把 Coco Framework 文档站从“带有营销页装饰的项目介绍”调整为“可快速定位、阅读和复制代码的技术文档产品”。第一优先级是让 Spring Boot/Java 开发者在首次进入时知道从哪里开始，在阅读功能文档时能稳定扫描标题、配置、代码和导航。

本次只处理 `coco-framework/website` 的前端体验，保留 Docusaurus 3、现有中英文路由、文档内容、SEO 元数据和代码示例。

## 2. 用户与核心场景

- 新用户从首页进入快速开始，并复制第一个 Starter 依赖。
- 已在使用 Coco 的开发者从侧边栏进入某个能力，快速判断适用范围、配置入口和替换点。
- 用户在长文档中通过侧边目录、页面目录、代码块和上一页/下一页持续阅读。
- 中文和英文用户在同一套信息结构中切换语言；浅色和深色模式下都保持清晰对比。

## 3. 现状问题

- 首页共有多个同等重量的分节，导致“开始接入”和“功能导览”不够突出。
- 奶油色、棕橙色、颗粒/渐变和多种悬浮效果共同占据视觉注意力，技术信息反而不够安静。
- 功能卡片、架构层、步骤、社区区块都使用相近的容器语言，层级和节奏重复。
- 文档页仍有部分营销式处理：标题渐变、暖色代码框、阴影和全局悬浮提升会干扰连续阅读。
- 已有动效较多，文档页需要保留状态提示和阅读进度，但不应让每个结构元素参与入场动画。

## 4. 设计方向

本次设计参考两个成熟开源文档项目的优点，但不把它们当作需要直接接入的依赖：借鉴 Starlight 的阅读宽度、侧边栏层级和内容优先布局，借鉴 Fumadocs 的组件化表达、代码示例和文档入口组织；具体实现继续落在现有 Docusaurus 主题、MDX 和 React 组件上。

### 4.1 总体气质

采用克制的“技术编辑台”视觉：中性浅色表面、深色正文、单一高识别品牌强调色，并用细边框和留白建立层级。保留 Coco 的品牌识别，但取消当前暖色装饰作为页面主叙事。

页面视觉令牌集中定义在 `website/src/css/custom.css`，组件 CSS 只引用令牌，不重复写颜色和阴影值。以下是实现基线；最终上线前用浏览器计算后的颜色做 WCAG AA 验证，正文与大文本/UI 组件分别满足 4.5:1 和 3:1，对焦点指示也满足 3:1。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--coco-canvas` | `#F7F8FA` | `#11161B` | 页面背景 |
| `--coco-surface` | `#FFFFFF` | `#181F26` | 导航、代码外框、功能项 |
| `--coco-surface-muted` | `#EEF1F4` | `#222B33` | 次级分区、代码标题栏、活动背景 |
| `--coco-text` | `#15202B` | `#F3F6F8` | 正文和标题 |
| `--coco-text-muted` | `#536170` | `#B7C1C9` | 辅助说明、元信息 |
| `--coco-border` | `#D9E0E7` | `#35404A` | 分隔线、容器边框 |
| `--coco-accent` | `#0F766E` | `#5EEAD4` | 链接、激活态、主要按钮、进度线 |
| `--coco-code-bg` | `#F1F4F6` | `#0D1318` | 代码内容区 |

- 页面背景使用冷中性浅灰/白；深色模式使用深墨色表面。
- 正文使用高对比深墨色；辅助文字只降低一级对比度。
- 强调色只用于链接、活动项、进度线、主要按钮和少量状态，不做大面积渐变。
- 容器最多 8px 圆角，优先使用平面分区和细边框；只给代码、表格、分页和重复功能项使用容器。
- 阴影仅保留令牌中的轻量层次，首页主视觉不使用大面积发光或厚重阴影。

### 4.2 首页结构

保留现有内容数据和双语字段，但重新组织首页的视觉权重：

1. **入口首屏**：品牌、清晰的一句话定位、两个主行动（快速开始/查看功能）和一个可复制的 Starter 代码面板。首屏下方只保留少量可信信息，不再用大段装饰铺满视口。
2. **能力导览**：把 6 个能力项按 Web、数据、可靠性/平台等职责组织为紧凑的导览列表或轻量网格，直接链接到现有文档路径。
3. **架构与边界**：用一条清晰的层级关系说明 Starter、Features、Foundation 与业务应用的职责，突出“减少重复基础设施，但不接管业务代码”。
4. **接入路径**：以 3-4 步说明从依赖到第一个接口，作为首页第二个明确入口。
5. **生态与社区**：压缩为低视觉重量的链接区，不与核心接入路径竞争。

当前的“痛点四卡片”和重复的编号分节不再作为独立主段落展示；相关信息改写为首页首屏或能力导览的辅助文案，避免内容丢失。

### 4.3 文档页

- 导航栏保持品牌、文档/技能、更新日志、语言和 GitHub，但缩小装饰和间距，让页面内容尽早进入视口。
- 左侧边栏强化分类标题、当前项和上下文间距；当前项使用明确的侧边强调线和浅色背景，不使用厚重胶囊。
- 正文设置稳定的最大阅读宽度；标题、首段、代码、表格和 admonition 之间形成连续的垂直节奏。
- 页面目录保持轻量，活动项通过文字颜色和细线表达，不做浮动卡片。
- H1 使用纯色高对比排版，取消渐变文字；H2/H3 用尺寸和间距区分，减少装饰性竖线。
- 代码块使用更平整的边框和标题栏，保持语法对比、复制按钮和横向滚动；不使用厚重暖色阴影。
- 表格、引用、提醒和分页维持可辨识边界，但统一为同一套边框、圆角和间距令牌。
- 保留现有“复制为 Markdown”和顶部阅读进度功能；复制状态需要有明确的键盘焦点和成功/失败反馈。

### 4.4 动效

- 保留文档路由切换的轻微透明度过渡和阅读进度线。
- 首页只保留首屏级别的轻微进入，以及必要的按钮/链接反馈。
- 移除文档正文逐项 reveal、功能卡片浮起、层级列表横移、计数器等会改变阅读节奏的效果。
- 所有动效继续服从 `prefers-reduced-motion`；没有 JavaScript 时首屏内容也必须完整可见。
- 内容默认以最终状态渲染；只有在组件挂载后由 JavaScript 添加动画类时才允许执行进入动画，禁止用初始 `opacity: 0` 隐藏 SSR 内容。
- `prefers-reduced-motion: reduce` 下取消进入、浮起、横移和计数器效果，但保留复制成功/失败等必要状态反馈。

### 4.5 可访问性

- 所有交互元素按 DOM 顺序可通过键盘 Tab 到达，`:focus-visible` 使用 `--coco-focus` 并保持至少 3:1 的可见对比度。
- 复制 Markdown 按钮保持原生 `<button>`，复制成功/失败通过同一组件内的 `aria-live="polite"` 状态文本反馈，不只依赖颜色或图标。
- 成功、失败、当前项和警告等状态同时使用文字、图标或结构表达，不能只依赖颜色。
- 主题切换继续使用 Docusaurus 的 color mode 机制；新增颜色令牌需在切换时同步映射，避免页面闪烁和文字短暂不可读。
- Logo、GitHub、语言切换、代码复制和外部链接具有完整的可访问名称；装饰性图标使用 `aria-hidden`。

## 5. 技术边界

### 允许修改

- `website/src/pages/index.tsx`
- `website/src/pages/index.module.css`
- `website/src/data/landing.ts`（只做结构需要的最小文案/字段调整）
- `website/src/css/custom.css`
- `website/src/theme/DocItem/Content/styles.module.css`
- `website/src/theme/DocItem/Content/useDocMotion.ts`
- 必要时调整 `website/docusaurus.config.ts` 的导航标签或主题配置，但不改路由契约

### 明确不做

- 当前不把底层框架迁移到 Starlight、Fumadocs、Rspress 或 Nextra；它们在本次工作中只作为信息架构和 UI 视觉参考。若后续发现 Docusaurus 无法满足搜索、版本管理或内容工作流，再单独评估迁移成本。
- 不修改 Java 模块、文档正文的业务含义、发布流程、SEO 插件和国际化路由。
- 不增加新的 UI 框架、图标库或图片依赖；继续使用仓库已有字体、Lucide、Docusaurus Prism 和 logo 资产。
- 不把业务示例、Admin 领域模型或 Generate 运行时能力写进 Framework 首页。

### 5.1 内容迁移与兼容

首页现有内容迁移到新结构时，按以下关系处理：

| 现有内容 | 新位置 | 兼容要求 |
| --- | --- | --- |
| `pains` 四项 | 首屏辅助文案和能力导览的边界说明 | 不再单独渲染为四张主卡片，但信息不能丢失 |
| `features` 六项 | 能力导览 | 保留现有文档路径和中英文标题 |
| `compare` 两段代码 | 首屏 Starter 面板或架构/边界段 | 保留“框架减少装配、业务仍由开发者掌控”的含义 |
| `layers` | 架构与边界 | 保留业务应用、Starter、Features、Foundation 四层关系 |
| `ecosystem` | 低视觉重量的生态/社区链接区 | 保留三个仓库的职责边界和外链 |
| `steps` | 接入路径 | 保留四步语义，并突出快速开始入口 |
| `community` | 页面末端社区区 | 保留讨论、Issue、贡献入口 |

当前公开的 `#capabilities` 必须继续指向能力导览。重构后新增的主要区块使用稳定的 `#architecture`、`#getting-started`、`#ecosystem` 和 `#community`，后续不得随意删除或复用。旧分节没有稳定的公开 `id`，不为不存在的锚点制造兼容假设；若实现阶段发现外部链接实际使用了其他锚点，则保留别名元素或在站点层增加重定向。

首页和每个 Markdown 文档都必须只保留一个语义 H1，H2/H3 不跳级；导航文字、页面标题和 SEO 元数据的大小写统一为 `Coco Framework`、`Starter`、`Features` 和 `Foundation`。

### 5.2 响应式行为

- 在 1440px、1024px 和 390px 视口都使用稳定的容器宽度和间距令牌，禁止通过负 margin 或脆弱的结构选择器修正布局。
- 移动端导航继续使用 Docusaurus 抽屉；侧边栏不常驻占宽，TOC 折叠为可展开区块。
- 首页首屏在 390px 下先呈现定位和 CTA，代码面板随后垂直排列；CTA 不被代码面板挤出首屏，也不依赖隐藏主要内容解决溢出。
- Starter 和文档代码块在移动端保持横向滚动，表格容器内部横向滚动，页面本身不能横向滚动。
- 长中文、英文复合词和按钮文案允许换行；按钮和导航不得依赖固定宽度截断文本。

### 5.3 国际化与长文本

- `website/src/data/landing.ts` 的 `zh` 与 `en` 字段结构必须保持同步；实现阶段优先用 TypeScript 约束或等价的构建检查发现字段漂移。
- `npm run check-translations` 必须从 `website` 目录执行，并与 CI 使用同一入口；若新增导航、页脚或主题文案，必须同步更新填充脚本或翻译资源。
- 视觉验收至少覆盖中文首页、英文首页、中文长标题文档和英文长标题文档，重点检查 CTA、导航、侧边栏、能力项和代码标题。

### 5.4 性能与维护

- 不增加图片、动画或运行时依赖；logo 等固定尺寸资源必须保留宽高，避免布局偏移。
- Lighthouse 移动端目标为 LCP < 2.5s、CLS < 0.1；若本地环境无法稳定测量，至少记录测量命令、视口和剩余原因，不把未测量结果写成通过。
- CSS 颜色、边框、圆角、间距和阴影集中使用令牌；避免依赖 Docusaurus 生成类名的脆弱选择器，确有必要时在代码中保留原因注释。
- 本次不引入 analytics；快速开始点击、依赖复制和搜索使用情况可作为后续产品指标单独讨论。
- 当前没有 axe/Lighthouse 自动化配置；实现阶段应优先使用现有本地检查方式，并在可行时增加不影响生产包的浏览器验收脚本。若需要 swizzle，必须记录对应 Docusaurus 升级风险。

## 6. 验收标准

- 在 `1440x900` 和 `390x844` 首屏内可见品牌定位、快速开始 CTA 和功能导览入口；移动端 CTA 在代码面板之前出现。
- 首页信息区块不再呈现为连续同质化卡片；六个能力入口仍直接对应现有文档路径。
- 页面级在 `1440px`、`1024px` 和 `390px` 视口无横向溢出；代码和表格只在自身容器内部横向滚动。
- 文档正文阅读列最大宽度约 `65-75ch`；侧边栏和 TOC 在桌面可用，在移动端按 5.2 的行为收起。
- 键盘 Tab 可到达所有交互元素，焦点始终可见；复制按钮可用键盘触发，成功/失败通过 `aria-live="polite"` 反馈。
- 使用 axe 或 Lighthouse 检查，不能有 serious/critical 可访问性问题；正文和大文本/UI 组件分别达到 4.5:1 和 3:1，对焦点指示达到 3:1。
- 浅色/深色模式下颜色令牌映射一致，切换无明显闪烁；状态不只依赖颜色表达。
- 中文/英文 landing 字段结构一致，长中文和英文文本不会撑破按钮、导航或能力项；`npm run check-translations` 在 `website` 目录通过。
- `prefers-reduced-motion: reduce` 下取消非必要进入、浮起、横移和计数器效果；SSR 或禁用 JavaScript 时首页内容从初始渲染即可见。
- 不改变现有文档链接、`#capabilities` 锚点、站点元数据、Markdown 复制功能和双语路由。
- 在可测环境中 Lighthouse 移动端达到 LCP < 2.5s、CLS < 0.1；记录无法稳定测量的环境限制。
- `npm run typecheck`、`npm run check-translations` 和 `npm run build` 在 `website` 目录通过，并运行一次 `codegraph sync .` 更新索引。

## 7. 修订 2026-10-09（二）：Claude 风格的复古雅致方向

> 本节追加于首版验收之后，**取代** §4.1 的色板、字体与气质描述；§1-§3 与 §4.2-§6 的结构、信息架构、无障碍、响应式与验收要求继续有效，除非本节明确覆盖。逐 token 的可实现取值与对比度计算见 `website/.agents/tasks/design-note.md`。

### 7.1 触发原因与对 §3 的修正

用户在浏览器实际验收后反馈：“现在的样式好丑，不如之前的呢”，希望“复古、但是高雅”，并推荐 Claude 风格。对照截图（`.superpowers/sdd/2026-10-09-coco-framework-docs-ui-redesign/visual/`），当前的冷灰 + teal 方案存在三个问题：全站只有一种无衬线字体，缺少层级与个性；冷灰白底配 teal 像通用 SaaS 后台，没有品牌温度（与 terracotta 的 Logo 也不协调）；平铺的细线和同质化版块读起来单薄。

§3 曾把“奶油色、棕橙色”列为问题。本次修正该判断：真正粗糙的是**渐变文字 H1、整块 tinted 色带、厚重阴影、卡片浮起、颗粒叠层和发光**，而不是暖色本身。保留暖色的温度，去掉这些处理。

### 7.2 气质

像一本排得很好的书，或 Anthropic/Claude 的官网：安静、文学感、克制。不使用拟物、像素字体、重纹理、霓虹、玻璃拟态、大面积渐变或发光。复古感只来自四件事：暖纸色表面、衬线标题、细线与双线分隔、等宽字母间距的小标签。不引入纸张噪点图（`custom.css` 的测试也禁止 `feTurbulence`）。

## 8. 修订 2026-10-09（三）：视口驱动的布局与动效

> 本节追加于 §7 验收之后。色板、字体与复古细节沿用 §7；本节**覆盖** §7.6 中“首页取消进入动画”一句，并补充布局与动效规则。

### 8.1 触发原因

用户在约 1024×490 的屏幕上验收后反馈：“没有任何动画效果，且没对齐视口，要根据视口宽高来，重新设计”。当时首屏内容挤在约 575px 宽的居中窄栏，右侧约 40% 留空，首屏没有铺满，页面完全静止。裁定：用户推翻“首页无动效”，改为 JS 门控的动效，并保留无 JS 与减少动效时的最终态。

### 8.2 布局系统

- 令牌（`custom.css`）：`--coco-gutter: clamp(1.25rem, 5vw, 7.5rem)`；`--coco-container: min(108rem, 100% - 2 × gutter)`；`--coco-viewport-h: calc(100svh - navbar)`（不支持 `svh` 时回退 `100vh`）。
- 字号同时受宽和高约束：`--coco-step-hero: max(2.25rem, min(1rem + 4.6vw, 11.5vh, 7.25rem))`，`--coco-step-2/3` 同样带 `vh` 上限；正文 `--coco-step-0: clamp(1rem, 0.9rem + 0.25vw, 1.25rem)`；区块间距 `--coco-section-space: clamp(3rem, 3.5vw + 4vh, 9rem)`。
- 首屏：`.hero` 最小高度为 `max(20rem, --coco-viewport-h)`，内部 grid 垂直居中。宽度 ≥1024px，或 ≥720px 宽且 ≤600px 高的横屏，采用两栏（文案 1.08fr / 代码面板 1fr），四项数据横跨底部；更窄时单栏，代码面板位于 CTA 之后。≥1024px 且高度 ≥700px 时标题拆为 “Coco / Framework” 两行，上限 `min(1rem + 5.2vw, 11vh, 8.5rem)`。高度 ≤640px、≤440px 两档逐级收紧行距与间距，数据值与标签同行，保证 1024×500、844×390 首屏完整。
- 文档页：导航与文档框架在超宽屏居中，侧栏与 TOC 的最大高度按视口计算，阅读列保持 65–75ch。

### 8.3 动效

- 门控：`docusaurus.config.ts` 的内联头部脚本在首帧前给 `<html>` 设置 `data-coco-motion`（减少动效或缺少 `IntersectionObserver` 时不设置）。CSS 只在该属性与 `prefers-reduced-motion: no-preference` 同时成立时隐藏或动画。首页 hook 把属性置为 `armed`；4 秒内未置为 `armed` 则脚本移除属性，所有内容直接显示。
- 首屏入场为纯 CSS 关键帧，首帧即开始，不等待水合：版本号与细线 → 标题两词 → 定位语 → 简介 → 两个 CTA → 代码面板 → 代码逐行擦入（clip-path）→ 接入说明。位移 10–24px，时长 650–900ms，`cubic-bezier(0.22, 1, 0.36, 1)`，错峰 70–90ms，无回弹。
- 滚动出现：`[data-reveal]` 进入视口时由 hook 设置 `data-in`，800ms 透明度 + 18px 上移，同屏错峰 80ms（上限 480ms）；分隔细线随后画出；步骤数字按 clip-path 从左向右显现；架构分层自 Foundation 向上依次落下（-14px）；数据在可见时 1200ms 递增计数（ease-out cubic，预留最终宽度，无布局位移）。
- 微交互：箭头图标 2–3px 位移；链接下划线与卡片顶线以 scaleX 画出；不抬升、不加阴影；主题切换按钮不抬升。
- 仅动画 `transform`、`opacity`、`clip-path`，CLS ≤ 0.05。键盘焦点落入未显示的区块时立即显示；打印前全部显示。
- 文档页保持安静：仅在真实路由切换时做 220ms 透明度过渡（首次挂载不淡入，保留 `previousRoute` 判断），外加阅读进度细线。
- 无 JS：属性不存在，全部内容为最终态。减少动效：无入场、无出现、无计数、无位移，复制成功/失败反馈照常。

### 8.4 追加验收

- 所有视口无页面级横向溢出；首屏高度 ≥（视口高 − 导航）× 90%，首屏内容不被裁切，两个 CTA 在首屏内。
- ≥1024px 宽时首屏内容横跨容器宽度 ≥80%，两栏并排；单栏时代码面板位于 CTA 之后。
- 动效帧、无 JS、阻断脚本后的 4 秒兜底、减少动效、键盘焦点显示均由 `scripts/check-docs-ui-browser.mjs` 覆盖；`scripts/test-docs-ui.mjs` 校验门控、减少动效回退与视口令牌。
- 截图供人工查看时，单边不超过 1600px（`visual/review/`）。
