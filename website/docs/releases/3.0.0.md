# 3.0.0 版本说明

**状态：未发布 · 主版本，包含破坏性变更**

## 破坏性变更

### 移除内置代码生成

以下能力已从框架中移除，由独立开发期工具 [coco-generate](https://github.com/patton174/coco-generate) 接管：

- Maven 制品 `io.github.patton174:coco-feature-codegen`，以及 `io.github.coco.feature.codegen` 包下的全部公开类型（`CocoCodeGenerator`、`CocoCodegenRequest`、`CocoCodegenResult`、`CocoCrudSpec`、`CocoGeneratedFileWriter`、`FreeMarkerCocoCodeGenerator` 等）。
- 功能标识 `codegen` 与枚举常量 `CocoFeature.CODEGEN`。
- `coco-maven-plugin` 的 `coco:generate` goal 及 `coco.codegen.*` 参数。
- 配置前缀 `coco.codegen.*` 与对应的配置元数据。
- `coco-spring-boot-starter` 不再传递依赖 `coco-feature-codegen` 与 FreeMarker。

移除原因见[代码生成](../features/codegen.md)。coco-generate 内置的 `crud` 模板与 2.x 框架模板逐字节一致，生成结果语义不变。

## 升级检查

1. 只依赖 `coco-parent` 与 `coco-spring-boot-starter` 的应用不需要修改 Java 代码；显式声明了 `coco-feature-codegen` 的 `pom.xml` 需删除该依赖。
2. 从 `coco.features.disabled`、`coco.features.enabled` 和 `@CocoFeatures` 中删除 `codegen`。残留的 `codegen` 会在 `coco:features` 构建期被拒绝，错误信息会指向 coco-generate；运行期由 Spring Boot 绑定 `coco.features.*` 时同样失败。
3. 删除对 `coco:generate` goal 的调用与 `coco.codegen.*` 配置，改用 `coco-generate plan` / `coco-generate generate`。参数对照见[代码生成](../features/codegen.md)。
4. 执行业务项目的构建与集成测试，确认打包产物中不再出现 `coco-feature-codegen-*.jar` 与 `freemarker-*.jar`。
