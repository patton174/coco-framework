# 3.0.0 Release Notes

**Status: unreleased · major version with breaking changes**

## Breaking changes

### Built-in code generation removed

The following capabilities were removed from the framework and are now owned by the standalone development-time tool [coco-generate](https://github.com/patton174/coco-generate):

- The Maven artifact `io.github.patton174:coco-feature-codegen` and every public type under the `io.github.coco.feature.codegen` package (`CocoCodeGenerator`, `CocoCodegenRequest`, `CocoCodegenResult`, `CocoCrudSpec`, `CocoGeneratedFileWriter`, `FreeMarkerCocoCodeGenerator`, and others).
- The `codegen` feature identifier and the `CocoFeature.CODEGEN` enum constant.
- The `coco:generate` goal of `coco-maven-plugin` and its `coco.codegen.*` parameters.
- The `coco.codegen.*` configuration prefix and its configuration metadata.
- `coco-spring-boot-starter` no longer pulls in `coco-feature-codegen` or FreeMarker transitively.

See [Code Generation](../features/codegen.md) for the rationale. The `crud` templates bundled with coco-generate are byte-for-byte identical to the 2.x framework templates, so generated output keeps the same semantics.

## Upgrade checklist

1. Applications that only depend on `coco-parent` and `coco-spring-boot-starter` need no Java changes; a `pom.xml` that declares `coco-feature-codegen` explicitly must drop that dependency.
2. Remove `codegen` from `coco.features.disabled`, `coco.features.enabled`, and `@CocoFeatures`. A leftover `codegen` entry is rejected by `coco:features` at build time with an error that points to coco-generate; Spring Boot binding of `coco.features.*` fails at runtime as well.
3. Replace invocations of the `coco:generate` goal and `coco.codegen.*` settings with `coco-generate plan` / `coco-generate generate`. The parameter mapping is documented in [Code Generation](../features/codegen.md).
4. Run your build and integration tests and confirm that the packaged archive no longer contains `coco-feature-codegen-*.jar` or `freemarker-*.jar`.
